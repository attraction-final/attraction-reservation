# 어트랙션 Q&A (Jev) 테스트 시나리오

## 1. 개요

어트랙션 Q&A는 로그인한 방문객이 자연어로 묻고, Jev는 어트랙션과 질문 의도만 분류하며, 답의 숫자는 DB에서 나온다. 아래 시나리오 20개는 이 동작을 정상 답변, 되묻기, 입력 검증, 장애의 네 묶음으로 확인한다. 기존 번호는 테스트 이름에서 참조하므로 바꾸지 않고, 추가한 시나리오는 17번부터 붙였다.

| 항목 | 내용 |
| --- | --- |
| 대상 API | `POST /api/attractions/questions` (body: `{"question": "..."}`) |
| 응답 type | `ANSWERED` / `NEED_CLARIFICATION` / `UNSUPPORTED` |
| 확신도 하한 | 0.6 (어트랙션·의도 각각) |
| 액터 | 방문객(로그인 사용자), 관리자, TypeSafe Jev(외부 시스템) |
| 전제 데이터 | `docs/sql/kan-117-attraction-ride-info-migration.sql` 적용 완료 |
| 전제 상태 | 렛츠 트위스트 = `MAINTENANCE`(관리자 API로 변경), 나머지 = `OPERATING` |

화면 단계는 프론트 Q&A 화면을 가정한 표현이다. 프론트 전에는 같은 요청을 Postman이나 curl로 보내고 응답 JSON의 `type`, `answer`, `candidates`로 판정한다.

Jev는 같은 질문에도 확신도가 조금씩 달라질 수 있다. 그래서 Jev 판단에 기대는 시나리오(6~8)는 응답 type과 후보 포함 여부로 판정하고, 문장을 글자 그대로 비교하는 것은 DB 값으로만 정해지는 시나리오에 한정한다.

## 2. 판정 순서

위에서부터 먼저 걸리는 규칙을 따른다.

| 순서 | 조건 | 응답 |
| --- | --- | --- |
| 1 | 의도가 `OTHER`이고 의도 확신도가 0.6 이상 | `UNSUPPORTED` |
| 2 | 어트랙션이 없음(`NONE`)이거나 어트랙션 확신도가 0.6 미만 | `NEED_CLARIFICATION` |
| 3 | 분류된 어트랙션이 조회한 목록에 없음 | `NEED_CLARIFICATION` |
| 4 | 의도 확신도가 0.6 미만 | `ANSWERED` (`intent`는 빈 값, 요약 답변) |
| 5 | 그 외 | `ANSWERED` |

되묻기 후보는 확률 0.1 이상인 어트랙션을 높은 순으로 최대 3개 보여주고, 없으면 전체 목록을 보여준다. `NONE`이 1순위여도 같은 규칙을 적용한다.

## 3. 테스트 시나리오

모든 시나리오의 전제 조건은 "로그인한 방문객"이며, 다른 전제가 필요하면 표의 전제 칸에 적었다.

### A. 정상 답변 (ANSWERED)

| 번호 | 시나리오 | 전제 | 질문 | 예상 결과 |
| --- | --- | --- | --- | --- |
| 1 | 키 제한 질문 | | `모니모러쉬 키제한 있어?` | `[모니모 러쉬] 키 130cm 이상이면 혼자 탈 수 있습니다. 키 195cm를 넘으면 탈 수 없습니다.` 띄어쓰기가 다른 이름을 같은 어트랙션으로 인식함 |
| 2 | 운영 시간 질문 | | `모니모 몇시까지 해?` | 의도 `OPERATING_HOURS`, `[모니모 러쉬] 운영 시간은 12:45 ~ 19:30입니다.` |
| 3 | 운영 상태 질문 (점검 중) | 렛츠 트위스트 `MAINTENANCE` | `렛츠트위스트 지금 탈 수 있어?` | 의도 `OPERATION_STATUS`, `[렛츠 트위스트] 현재 점검 상태입니다.` |
| 4 | 점검 중인 어트랙션의 키 제한 | 렛츠 트위스트 `MAINTENANCE` | `렛츠 트위스트 키 제한 알려줘` | `[렛츠 트위스트] 키 140cm 이상이면 혼자 탈 수 있습니다. 키 195cm를 넘으면 탈 수 없습니다. 단, 현재 점검 상태입니다.` |
| 5 | 보호자 동반 기준 | | `아마존 익스프레스 아이 혼자 탈 수 있어?` | `[아마존 익스프레스] 키 110cm를 초과하면 혼자 탈 수 있습니다. 키 110cm 이하는 보호자와 함께 타야 합니다.` |

### B. 되묻기·요약·미지원

| 번호 | 시나리오 | 전제 | 질문 | 예상 결과 |
| --- | --- | --- | --- | --- |
| 6 | 어트랙션이 모호한 질문 | | `롤러코스터 키 제한 알려줘` | `NEED_CLARIFICATION`, "어떤 어트랙션을 말씀하시는지 확실하지 않습니다" 안내, 후보는 최대 3개이고 확률 0.1 이상인 후보가 없으면 전체 목록. 후보를 골라 다시 물으면 `ANSWERED`. 틀린 키 수치를 추측해 답하지 않음 |
| 7 | 어트랙션 언급이 없는 질문 | | `키 제한 있는 거 뭐야?` | `NEED_CLARIFICATION`, 후보가 없으면 등록된 어트랙션 전체가 선택지로 표시됨 |
| 8 | 무엇을 묻는지 애매한 질문 | | `모니모 러쉬 어때?` | 의도 확신도가 0.6 미만이면 `ANSWERED`, `intent`는 빈 값. 키 제한, 운영 시간, 운영 상태를 한 문단으로 요약하고 접두어 `[모니모 러쉬]`는 한 번만 나옴 |
| 9 | 지원하지 않는 질문 | | `아마존 가격 얼마야?` | `UNSUPPORTED`, `지금은 어트랙션의 키 제한, 운영시간, 운영 상태만 안내할 수 있습니다.` |
| 10 | 키 제한 정보가 없는 어트랙션 | 키 관련 값이 모두 NULL | 그 어트랙션의 키 제한 질문 | `[어트랙션 이름] 등록된 키 제한 정보가 없습니다. 현장 안내를 확인해 주세요.` "키 제한이 없습니다"라고 단정하지 않음 |
| 17 | 운영 시간 정보가 없는 어트랙션 | 렛츠 트위스트 `MAINTENANCE`, 운영 시간 NULL | `렛츠 트위스트 몇시까지 해?` | `[렛츠 트위스트] 등록된 운영 시간 정보가 없습니다. 현장 안내를 확인해 주세요. 단, 현재 점검 상태입니다.` |
| 18 | 일시중단 중인 어트랙션 | 모니모 러쉬 `SUSPENDED` | `모니모 러쉬 키 제한 알려줘` | `[모니모 러쉬] 키 130cm 이상이면 혼자 탈 수 있습니다. 키 195cm를 넘으면 탈 수 없습니다. 단, 현재 일시중단 상태입니다.` |
| 19 | 삭제된 어트랙션 | 범퍼카 삭제 처리 | `범퍼카 키 제한 알려줘` | Jev에 보내는 선택지와 후보에서 제외되어 범퍼카 정보를 답하지 않음 |

| 번호 | 시나리오 | 입력 | 예상 결과 |

### D. 장애·운영

**시나리오 14: Jev API 키 미설정**

환경변수 `SPRING_AI_TYPESAFE_APIKEY` 없이 서버를 실행한다.

- 서버가 정상 기동되고 어트랙션 목록 등 다른 기능은 정상 동작한다.
- Q&A는 503, `지금은 어트랙션 질문에 답할 수 없습니다. 잠시 후 다시 시도해 주세요.`로 응답한다.
- 로그에 `event=ATTRACTION_QNA_JEV_FAILED target=jev reason="API 키 미설정"`이 남는다.

**시나리오 15: Jev 장애·타임아웃**

잘못된 API 키를 넣거나 네트워크를 끊어 Jev에 닿지 못하게 한다. 어떤 경우든 503과 재시도 안내 문구로 응답한다.

| 상황 | 재시도 | 로그의 `exceptionType` |
| --- | --- | --- |
| 400 잘못된 요청 | 없음 | `TypeSafeBadRequestException` |
| 401 키 오류 | 없음 | `TypeSafeAuthenticationException` |
| 422 처리 불가 | 없음 | `TypeSafeUnprocessableEntityException` |
| 429 호출 한도 초과 | 1번 | `TypeSafeRateLimitException` |
| 500 서버 오류 | 1번 | `TypeSafeInternalServerException` |
| 529 과부하 | 1번 | `TypeSafeOverloadedException` |
| 응답 지연 (요청당 2초) | 1번 | `TypeSafeApiTimeoutException` |
| 연결 실패 | 1번 | `TypeSafeApiConnectionException` |

- 재시도를 포함해 5초 안에 응답한다(`total-timeout: 5s`). `Retry-After`가 남은 시간보다 길면 기다리지 않고 바로 503으로 응답한다.
- 로그에 `event=ATTRACTION_QNA_JEV_FAILED`(WARN)와 예외 종류가 남고, 이어서 `event=REQUEST_FAILED ... httpStatus=503`(ERROR)이 남는다.

**시나리오 16: 개인정보가 로그에 남지 않음**

`우리 딸 지우 키 105인데 썬더폴스 탈 수 있어?`로 질문한다.

- 썬더폴스 키 제한(100cm 이상)이 `ANSWERED`로 출력된다.
- `ATTRACTION_QNA_CLASSIFIED` 줄에는 `target`, `durationMs`, `questionLength`, `attractionId`, 확신도, 의도, 모델, `inputTokens`만 남고 질문 원문은 없다.
- Jev가 오류 응답에 질문을 되돌려줘도 로그에 남지 않는다. 예외 메시지에 응답 본문이 들어가므로 예외 객체를 로그로 넘기지 않는다.

**시나리오 20: Jev 응답을 해석할 수 없음**

Jev가 200으로 응답했지만 JSON이 아니거나, 답이 빠져 있거나, 보내지 않은 옵션을 돌려준다.

- 추측해서 답하지 않고 503으로 응답한다.
- 로그에 `event=ATTRACTION_QNA_JEV_FAILED`와 예외 종류가 남고, 응답 값은 남지 않는다.

## 4. 추적표

관리자 유스케이스(UC-7)만 시나리오가 없다. 아직 API가 없어 SQL로 넣기 때문이다.

| 유스케이스 | 관계 | 확인하는 시나리오 |
| --- | --- | --- |
| UC-1 어트랙션 질문하기 | 방문객의 기본 유스케이스 | 11, 12 (입력 검증) |
| UC-1.1 키 제한 확인 | UC-1의 일반화 | 1, 4, 5, 10, 16, 18 |
| UC-1.2 운영 시간 확인 | UC-1의 일반화 | 2, 17 |
| UC-1.3 운영 상태 확인 | UC-1의 일반화 | 3, 18 |
| UC-2 질문 분류하기 (Jev) | UC-1이 항상 포함 | 1~9, 14, 15, 17~20 |
| UC-3 로그인 인증 | UC-1이 항상 포함 | 13 |
| UC-4 후보 다시 고르기 | 어트랙션 확신도 < 0.6일 때 확장 | 6, 7, 19 |
| UC-5 정보 요약 받기 | 의도 확신도 < 0.6일 때 확장 | 8 |
| UC-6 미지원 안내 받기 | 의도 = OTHER일 때 확장 | 9 |
| UC-7 탑승 정보 관리 (예정) | 관리자 | 없음 (전제 데이터로만 사용) |
