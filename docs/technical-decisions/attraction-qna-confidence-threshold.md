# 확신도 0.6 기준으로 답변 · 요약 · 되묻기 · 미지원 나누기

> 분류: 기술적 도전 · 관련 이슈: KAN-116, KAN-122 · 기준 코드: `dev` `AttractionQuestionService#answer`

| 항목 | 내용 |
| --- | --- |
| 문제 | Jev는 애매한 질문에도 하나를 고른다. 고른 값을 그대로 믿으면 틀린 어트랙션의 수치를 답하게 된다 |
| 결정 | 어트랙션 · 의도 확신도가 각각 0.6 이상일 때만 믿는다. 판정 순서는 미지원 → 되묻기 → 요약 → 답변 |
| 근거 | 어트랙션이 불확실하면 어떤 숫자도 답할 수 없고, 의도만 불확실하면 요약으로 충분하다 |
| 한계 | 0.6을 정할 때 본 응답 분포는 기록하지 않았다 |

## 1. 문제

"롤러코스터 키 제한 알려줘"처럼 여러 어트랙션에 걸치는 질문이나, "모니모 러쉬 어때?"처럼 무엇을 묻는지 애매한 질문이 들어온다. Jev는 이때도 하나를 고르므로, 고른 값을 그대로 믿으면 틀린 어트랙션의 수치를 답하게 된다.

## 2. 결정

위에서부터 먼저 걸리는 규칙을 따른다.

| 순서 | 조건 | 응답 |
| --- | --- | --- |
| 1 | 의도가 `OTHER`이고 의도 확신도 ≥ 0.6 | `UNSUPPORTED`: 키 제한 · 운영 시간 · 운영 상태만 안내한다고 알림 |
| 2 | 어트랙션이 `NONE`이거나 어트랙션 확신도 < 0.6 | `NEED_CLARIFICATION`: 후보를 보여 주고 다시 고르게 함 |
| 3 | 분류된 어트랙션이 조회한 목록에 없음 | `NEED_CLARIFICATION` |
| 4 | 의도 확신도 < 0.6 | `ANSWERED`: 키 제한 · 운영 시간 · 상태를 한 문단으로 요약 |
| 5 | 그 외 | `ANSWERED`: 물은 항목만 답변 |

되묻기 후보는 선택지별 확률이 0.1 이상인 어트랙션을 높은 순으로 **최대 3개** 보여 준다. 그런 후보가 없으면 전체 목록을 보여 준다.

## 3. 근거

- **어트랙션이 불확실하면 숫자를 하나도 답할 수 없다.** 그래서 어트랙션 판정이 의도 판정보다 앞선다.
- **의도만 불확실하면 버릴 필요가 없다.** 어트랙션은 확실하므로 세 정보를 모두 요약해 주면 사용자가 원하는 답이 그 안에 있다.
- **Jev 문서는 Choice 판단에 선택지 확률을 쓰라고 안내한다.** 1순위 값뿐 아니라 선택지별 확률을 받아, `NONE`이 1순위여도 확률이 남은 어트랙션을 후보로 좁혀 보여 준다.
- **목록에 없는 ID는 믿지 않는다.** 포트 계약상 없어야 할 일이지만, 틀린 어트랙션을 답하는 것보다 되묻는 편이 낫다.
- 0.6은 처음에 잠정값으로 두고, KAN-122에서 실제 Jev 응답으로 시나리오를 돌려 본 뒤 확정했다.

검증: `AttractionQuestionServiceTest`

| 테스트 | 확인 내용 |
| --- | --- |
| `answer_answered` | 의도와 어트랙션이 확실하면 그 어트랙션 문구로 답한다 (시나리오 1) |
| `answer_summary` | 의도가 불확실하면 intent 없이 요약한다 (시나리오 8) |
| `answer_unsupported` | 지원하지 않는 질문은 문구를 조립하지 않는다 (시나리오 9) |
| `answer_needClarification_topThreeCandidates` | 확률 높은 순 최대 3개, 키 수치를 추측하지 않는다 (시나리오 6) |
| `answer_needClarification_allAttractionsWhenNoCandidate` | 후보가 없으면 전체 목록 (시나리오 7) |
| `answer_needClarification_whenClassifiedAttractionIsMissing` | 목록에 없는 ID면 되묻는다 |

## 4. 한계

- 0.6을 정할 때 본 응답 분포는 문서로 남기지 않았다. 질문 유형이 늘면 다시 측정해야 한다.
- Jev는 같은 질문에도 확신도가 조금씩 다르다. 그래서 Jev 판단에 기대는 시나리오(6 ~ 8)는 문장 대신 응답 type과 후보 포함 여부로 판정한다.
