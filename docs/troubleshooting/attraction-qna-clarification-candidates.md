# 되묻기 후보 기대값과 실제 Jev 응답 불일치 트러블슈팅

> **KAN-122 · 어트랙션 Q&A 확신도 기준값 확정 (`AttractionQuestionService#pickCandidates`)**

| 항목 | 핵심 내용 |
| --- | --- |
| 배경 | 확신도 기준 0.6은 잠정값이었다. 시나리오 문서에 "실제 Jev 응답으로 확인한 뒤 확정한다"고 적어 두었다 |
| 증상 | 시나리오 6("롤러코스터 키 제한 알려줘")은 "후보 최대 3개"를 기대했지만, 실제로는 등록된 어트랙션 전체가 후보로 나왔다 |
| 원인 | 실제 Jev 응답은 `NONE` 확률이 0.94였고, 확률 0.1 이상인 어트랙션이 하나도 없었다. 코드는 이때 전체 목록을 주는데, 시나리오 문서가 이 규칙을 빠뜨렸다 |
| 처리 | 코드는 그대로 두고 시나리오 6의 기대값과 판정 규칙 문구를 코드와 맞췄다. 0.6을 확정했다 |
| 남은 범위 | 0.6을 정할 때 본 응답 분포는 기록하지 않았다 |

## 1. 동작 규칙

어트랙션이 `NONE`이거나 확신도가 0.6 미만이면 되묻는다(`NEED_CLARIFICATION`). 이때 보여 줄 후보는 다음과 같이 고른다.

```java
List<AttractionCandidate> likelyCandidates = candidates.stream()
        .filter(candidate -> probabilities.getOrDefault(candidate.attractionId(), 0.0)
                >= MIN_CANDIDATE_PROBABILITY)      // 0.1
        .sorted(/* 확률 높은 순 */)
        .limit(MAX_CANDIDATES)                     // 3
        .toList();
return likelyCandidates.isEmpty() ? candidates : likelyCandidates;
```

- `NONE`이 1순위여도 확률이 남은 어트랙션이 있으면 후보로 좁혀 보여 준다.
- 확률 0.1 이상인 어트랙션이 없으면 **전체 목록**을 보여 준다.

## 2. 증상

시나리오 6의 기대 결과는 "후보 최대 3개"였다. "롤러코스터"라는 말이 여러 어트랙션에 걸치므로, 롤러코스터 계열 어트랙션 몇 개가 후보로 좁혀질 것이라고 예상했다.

실제 Jev로 돌려 보니 등록된 어트랙션 전체가 후보로 나왔다.

## 3. 원인

| 확인 | 결과 |
| --- | --- |
| Jev 응답 | 어트랙션 선택지에서 `NONE` 확률 0.94 |
| 확률 0.1 이상인 어트랙션 | 없음 |
| 코드 동작 | 후보가 비면 전체 목록 → **정상 동작** |
| 시나리오 문서 | 2장 판정 규칙에는 "없으면 전체 목록"이 있었지만, 시나리오 6의 기대값에는 빠져 있었다 |

Jev는 "롤러코스터"를 특정 어트랙션이 아니라 "목록에 없는 것"으로 판단했다. `NONE`을 뺀 나머지 확률이 0.06뿐이라 어느 어트랙션도 0.1을 넘을 수 없었다. 코드는 의도대로 동작했고, 틀린 것은 문서의 기대값이었다.

## 4. 처리

| 대상 | 전 | 후 |
| --- | --- | --- |
| 확신도 하한 | `0.6 (어트랙션 · 의도 각각). 실제 Jev 응답으로 확인한 뒤 확정한다` | `0.6 (어트랙션 · 의도 각각)` |
| 시나리오 6 기대값 | `후보 최대 3개` | `후보는 최대 3개이고 확률 0.1 이상인 후보가 없으면 전체 목록` |

- 코드는 바꾸지 않았다. 숫자를 추측해 답하지 않고 되묻는다는 목표는 이미 지켜지고 있었다.
- 같은 규칙을 단위 테스트로 고정했다 (`AttractionQuestionServiceTest`).
  - `answer_needClarification_topThreeCandidates`: 확률 높은 순으로 최대 3개
  - `answer_needClarification_excludesLowProbability`: 하한 미만은 후보에서 뺀다
  - `answer_needClarification_allAttractionsWhenNoCandidate`: 후보가 없으면 전체 목록

## 5. 남은 확인

- 0.6을 정할 때 본 응답 분포(질문별 확신도)는 기록하지 않았다. 질문 유형이 늘면 다시 측정하고 기록해야 한다.
- 전체 목록은 어트랙션이 많아지면 길어진다. 그때는 "후보가 없으면 전체 목록" 대신 다른 안내가 필요할 수 있다.

## 6. 배운 점

- 외부 AI의 확률은 사람이 기대하는 "애매함"과 다르게 나온다. "롤러코스터"는 사람에게는 여러 후보가 있는 질문이지만, Jev에게는 "목록에 없음"이었다.
- 확률 기반 규칙은 실제 응답으로 시나리오를 돌려 본 뒤에 확정해야 한다. 잠정값으로 두고 확인 단계를 남겨 둔 것이 불일치를 찾는 데 도움이 됐다.
- 문서와 코드가 다를 때 어느 쪽이 맞는지 먼저 따져야 한다. 이번에는 코드가 맞고 문서의 기대값이 틀렸다.
