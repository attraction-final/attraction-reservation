# 테스트 규칙

- 테스트는 `given - when - then` 구조로 작성한다.
- 테스트명은 `메서드명_상황_기대결과` 형태로 작성한다.
- `@DisplayName`으로 테스트 의도를 설명한다.
- 정상 상황과 예외 상황을 모두 검증한다.
- 하나의 테스트는 하나의 핵심 동작을 검증한다.
- 기능을 추가·수정하면 관련 테스트를 작성하거나 실행한다.

```java
@Test
@DisplayName("예약 가능한 시간대라면 예약에 성공한다")
void createReservation_AvailableTimeSlot_Success() {
    // given
    // when
    // then
}
```

## 예약 도메인 테스트 예시
- 예약 가능한 시간대에 예약 성공
- 정원이 가득 찬 시간대에 예약 실패
- 존재하지 않는 예약 조회 시 예외 발생
- 예약 취소 후 잔여 좌석 증가
- 동일 사용자의 중복 예약 방지
- 동시 요청에도 정원 초과 방지

위 목록은 예약 도메인에만 적용하고 다른 도메인에는 해당 도메인의 핵심 규칙에 맞는 테스트를 작성한다.
