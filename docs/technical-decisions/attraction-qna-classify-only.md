# 생성형 AI의 잘못된 수치 막기: AI는 분류만, 답의 숫자는 DB에서

> 분류: 기술적 도전 · 관련 이슈: KAN-116, KAN-118, KAN-119 · 기준 코드: `dev` `JevAttractionQuestionClassifier`, `AttractionAnswerComposer`

| 항목 | 내용 |
| --- | --- |
| 문제 | AI가 키 제한 같은 수치를 직접 답하면 그럴듯하지만 틀린 값을 말할 수 있다. 안전과 직결된 정보다 |
| 결정 | Jev에는 "어느 어트랙션의 무엇을 묻는지" 선택지만 고르게 하고, 답 문장은 DB 값으로 조립한다 |
| 근거 | AI 출력이 정해 둔 선택지로 제한되므로 답의 숫자가 DB와 다를 수 없다 |
| 한계 | 키 제한 · 운영 시간 · 운영 상태 밖의 질문(가격, 위치, 대기 시간)은 답하지 못한다 |

## 1. 문제

"모니모 러쉬 키 제한 있어?"에 생성형 AI가 직접 답하면, 그럴듯하지만 틀린 키 수치를 말할 수 있다. 키 제한은 안전과 직결되는 정보라 한 번이라도 틀리면 안 된다.

## 2. 결정

- Jev에는 **선택지(Choice) 두 개**만 묻는다.
  - `attraction`: 어느 어트랙션인지 (삭제되지 않은 어트랙션 목록 + `NONE`)
  - `intent`: 무엇을 알고 싶은지 (`HEIGHT_LIMIT` · `OPERATING_HOURS` · `OPERATION_STATUS` · `OTHER`)
- 답변 문장은 `AttractionAnswerComposer`가 **DB에 저장된 값**으로 조립한다. 모든 답에 `[어트랙션 이름]` 접두어를 붙인다.
- 값이 비어 있으면 "키 제한이 없습니다"라고 단정하지 않고 "등록된 키 제한 정보가 없습니다. 현장 안내를 확인해 주세요."로 답한다 (시나리오 10, 17).
- 점검(`MAINTENANCE`) · 일시중단(`SUSPENDED`) 중이면 답변 끝에 현재 상태를 덧붙인다 (시나리오 4, 18).

## 3. 근거

- AI 출력은 "정해 둔 선택지 중 하나"로 제한되므로, 답의 숫자가 DB와 다를 수 없다.
- 어트랙션 정보가 바뀌어도 프롬프트를 고칠 필요가 없다. DB만 바꾸면 답이 바뀐다.
- 답 문장 조립은 외부 호출 없이 단위 테스트(`AttractionAnswerComposerTest`)로 검증한다.

## 4. 한계

- 지원 범위 밖 질문(`OTHER`)은 "지금은 어트랙션의 키 제한, 운영시간, 운영 상태만 안내할 수 있습니다."로 답한다. 범위를 넓히려면 의도와 DB 컬럼을 함께 늘려야 한다.
