# 비즈니스 규칙 (Business Rules)

## 0. 개요와 용어 정의

이 문서는 기획안(2026-10-13 초안)과 MVP 기능 목록을 바탕으로, 구현과 테스트의 기준이 되는 비즈니스 규칙을 도메인별로 정리한 것입니다. 각 규칙은 ID를 가지며 테스트 케이스와 예외 코드가 이 ID를 참조합니다.  문서 간 충돌은 9장에 모았습니다.

### 규칙 ID 체계

| 접두어    | 도메인      | 관련 테이블                                           |
|--------|----------|--------------------------------------------------|
| BR-USR | 회원·인증    | USER                                             |
| BR-TKT | 입장권      | TICKET_PRODUCT, TICKET                           |
| BR-PAY | 주문·결제·환불 | ORDERS, ORDER_ITEM, PAYMENT, REFUND, REFUND_ITEM |
| BR-ATR | 어트랙션     | ATTRACTION                                       |
| BR-SLT | 어트랙션 슬롯  | ATTRACTION_SLOT                                  |
| BR-RSV | 어트랙션 예약  | RESERVATION                                      |
| BR-RTE | 루트 추천    | ROUTE_RECOMMENDATION, ROUTE_RECOMMENDATION_STOP  |
| BR-COM | 공통       | —                                                |

### 용어 정의

시간 계산 기준이 팀원마다 달라지는 리스크(기획안 11장)를 막기 위해 아래 정의를 모든 도메인에서 동일하게 사용합니다.

| 용어        | 정의                                          | 예시                            |
|-----------|---------------------------------------------|-------------------------------|
| 방문일       | 입장권으로 놀이공원을 이용하는 날짜 1일                      | 2026-10-20                    |
| 이용 가능 시간  | 입장권 종류별로 어트랙션을 이용할 수 있는 시간대                 | 종일권 개장~폐장, 오후권 15:00~폐장       |
| 슬롯        | 어트랙션의 실제 탑승 시작·종료 시각과 정원을 가진 예약 단위          | 롤러코스터 14:00~14:10, 정원 20명     |
| 탑승 소요 시간  | 슬롯 종료 시각 − 슬롯 시작 시각                         | 10분                           |
| 이동 시간     | 두 지점(정문 또는 어트랙션) 사이의 예상 이동 시간(가상 데이터, 분 단위) | 정문→롤러코스터 8분                   |
| 대기 시간     | 다음 슬롯 시작 시각 − 해당 어트랙션 도착 시각                 | 14:00 − 13:52 = 8분            |
| 총 소요 시간   | 루트 전체의 이동 시간 합 + 대기 시간 합 + 탑승 소요 시간 합       | 이동 25분 + 대기 30분 + 탑승 20분= 75분 |
| 예약 마감 시각  | 슬롯 시작 시각 − 30분                              | 14:00 슬롯 → 13:30              |
| 사용자 이용 시간 | 추천 요청 시 사용자가 입력한 시작·종료 시각                   | 13:00~18:00                   |

## 1. 회원·인증 (BR-USR)

회원은 이메일로 가입하며, 활성 상태인 회원만 로그인과 예약을 할 수 있습니다. 관리자는 자체 가입 없이 시스템이 발급합니다.

| ID        | 규칙                                                                              | 위반 시 처리        |
|-----------|---------------------------------------------------------------------------------|----------------|
| BR-USR-01 | 이메일은 회원 전체에서 유일해야 한다(탈퇴 회원  포함 여부는 9장).                                         | 가입 거부          |
| BR-USR-02 | 비밀번호는 8~20자, 영문·숫자·특수문자를 각 1자 이상 포함하고 암호화(BCrypt)해 저장한다.                        | 가입·변경 거부       |
| BR-USR-03 | 일반 가입 시 권한은 항상 USER이다. ADMIN 계정은 시스템 또는 팀이 직접 발급한다.                             | —              |
| BR-USR-04 | Access Token 유효 시간 10분, Refresh Token 7일. Refresh Token은 서버(DB 또는 Redis)에 저장한다. | 만료 시 401       |
| BR-USR-05 | 로그아웃 시 해당 Refresh Token을 폐기하며, 폐기된 토큰으로 재발급할 수 없다.                              | 재발급 거부         |
| BR-USR-06 | ACTIVE 상태만 로그인할 수 있다. INACTIVE·SUSPENDED·WITHDRAWN은 로그인 불가.                     | 로그인 거부(상태별 안내) |
| BR-USR-07 | 닉네임·비밀번호만 본인이 수정할 수 있다. 비밀번호 변경 시 현재 비밀번호를 확인한다.                                | 수정 거부          |
| BR-USR-08 | 탈퇴는 소프트 삭제(상태 WITHDRAWN + 탈퇴 일시 기록)로 처리한다.                                      | —              |
| BR-USR-09 | 이용 예정인 예약 또는 미사용 입장권이 있으면 탈퇴 전에 처리 방식을 안내한다(9장 참고).                             | 탈퇴 보류          |
| BR-USR-10 | 관리자 API(/api/admin/**)는 ADMIN 권한만 호출할 수 있다.                                     | 403            |

### 회원 상태 전이

| 현재 상태         | 변경 가능 상태            | 변경 주체 |
|---------------|---------------------|-------|
| ACTIVE(활성)    | INACTIVE, SUSPENDED | 관리자   |
| ACTIVE(활성)    | WITHDRAWN           | 본인    |
| INACTIVE(비활성) | ACTIVE              | 관리자   |
| SUSPENDED(정지) | ACTIVE              | 관리자   |
| WITHDRAWN(탈퇴) | 변경 불가               | —     |

정지 처리 시 [제안] 해당 회원의 Refresh Token을 모두 폐기해 즉시 재발급을 막습니다.

## 2. 입장권 (BR-TKT)

입장권은 방문일 하루에만 유효하며, 종류에 따라 이용 가능 시간이 다릅니다. 결제 완료 시 구매 수량만큼 개별 입장권이 발급됩니다.

### 상품 정책

| 상품    | 이용 가능 시간   | 비고                    |
|-------|------------|-----------------------|
| 종일이용권 | 개장 ~ 폐장    | 가상 공원 운영 10:00~22:00  |
| 오후이용권 | 15:00 ~ 폐장 | 15:00 이전 슬롯은 예약·추천 불가 |

어트랙션 이용료는 입장권에 포함되며, 어트랙션별 추가 결제는 없습니다.

### 구매·발급·검증 규칙

| ID        | 규칙                                                                                            | 위반 시 처리 |
|-----------|-----------------------------------------------------------------------------------------------|---------|
| BR-TKT-01 | 판매 상태가 ON_SALE인 상품만 구매할 수 있다.                                                                 | 주문 거부   |
| BR-TKT-02 | 방문일은 구매일(오늘) 포함 30일 이내에서 선택한다. 지난 날짜는 불가.                                                     | 주문 거부   |
| BR-TKT-03 | 한 회원이 여러 장 구매할 수 있다. (구매 수량 제한 없음)                                                            | —       |
| BR-TKT-04 | 결제 완료 시점에 수량만큼 TICKET을 개별 발급하며, 각 입장권은 고유 번호·소유자·방문일·상품 종류를 가진다.                              | —       |
| BR-TKT-05 | 결제가 완료되지 않은 주문에는 입장권을 발급하지 않는다.                                                               | —       |
| BR-TKT-06 | 예약·추천에 사용하는 입장권은 다음을 모두 만족해야 한다: 소유자 = 요청 회원, 상태 = 사용중, 방문일 = 슬롯 날짜, 슬롯 시작 시각 ≥ 입장권 이용 시작 시각. | 예약 거부   |
| BR-TKT-07 | 미사용/사용 완료/환불/만료 입장권으로는 예약·추천할 수 없다.                                                           | 예약 거부   |
| BR-TKT-08 | 관리자의 가격 변경은 이후 주문부터 적용되며, 기존 주문 금액은 바뀌지 않는다(BR-PAY-03).                                       | —       |
| BR-TKT-09 | 판매 중지(STOPPED)된 상품도 이미 발급된 입장권은 유효하다.                                                         | —       |

### 입장권 상태 전이

| 현재 상태           | 다음 상태         | 조건                     |
|-----------------|---------------|------------------------|
| 미사용 (UNUSED)    | 사용중 (IN_USE)  | 입장 확인 API 기능 사용        |
| 미사용             | 환불 (REFUNDED) | 환불 완료(BR-PAY 환불 규칙)    |
| 미사용             | 만료 (EXPIRED)  | 방문일 폐장 시각 경과(사용 이력 없음) |
| 사용중             | 사용 완료 (USED)  | 방문일 폐장 시각 경과           |
| 사용 완료 · 환불 · 만료 | 변경 불가         | —                      |

## 3. 주문·결제·환불 (BR-PAY)

결제 금액은 서버가 계산한 주문 금액과 PG 승인 금액이 일치할 때만 확정하며, 환불은 입장권 단위로 부분 환불할 수 있습니다. 어트랙션 예약 취소에는 환불이 없습니다.

### 주문·결제 규칙

| ID        | 규칙                                                    | 위반 시 처리  |
|-----------|-------------------------------------------------------|----------|
| BR-PAY-01 | 주문 생성 시 주문은 결제 대기 상태로 시작한다.                           | —        |
| BR-PAY-02 | 주문 금액은 서버가 상품 가격 × 수량으로 계산한다. 클라이언트가 보낸 금액은 신뢰하지 않는다. | —        |
| BR-PAY-03 | ORDER_ITEM에 주문 시점의 단가를 저장하고, 이후 상품 가격이 바뀌어도 변경하지 않는다. | —        |
| BR-PAY-04 | PG 승인 금액 ≠ 주문 금액이면 결제를 확정하지 않고 승인을 취소한다.              | 결제 실패 처리 |
| BR-PAY-05 | 같은 주문에 대한 결제 승인은 1회만 처리한다(중복 콜백·재시도 시 멱등 처리).         | 중복 요청 무시 |
| BR-PAY-06 | 결제 대기 상태가 30분 지나면 주문을 자동 취소한다. (DEVELOPE에서 구현)        | 주문 취소    |
| BR-PAY-07 | PG는 테스트 모드로만 연동하며 실제 결제는 발생하지 않는다.                    | —        |

### 주문·결제 상태

기획 문서의 상태 목록에는 주문 상태와 결제 상태가 섞여 있어, 테이블별로 나누는 것을 제안합니다.

| 대상      | 상태                    | 전이                                |
|---------|-----------------------|-----------------------------------|
| ORDERS  | 결제 대기 → 주문 완료 / 주문 취소 | 결제 완료 시 주문 완료, 미결제·사용자 취소 시 주문 취소 |
| PAYMENT | 결제 대기 → 결제 완료 / 결제 취소 | 결제 완료 후 환불 시 부분 환불 → 환불 완료        |
| REFUND  | 요청 → 완료 / 실패          | PG 환불 응답 기준                       |

### 환불 규칙

| ID        | 규칙                                                           | 위반 시 처리 |
|-----------|--------------------------------------------------------------|---------|
| BR-PAY-10 | 환불은 입장권 단위로 요청하며, 한 주문 중 일부 입장권만 환불할 수 있다(부분 환불).            | —       |
| BR-PAY-11 | 미사용 상태 입장권만 환불할 수 있다.                                        | 환불 거부   |
| BR-PAY-12 | 방문일 전날 23:59까지 전액 환불, 방문일 당일부터는 환불 불가.                       | 환불 거부   |
| BR-PAY-13 | 환불 금액 = 해당 입장권의 주문 시점 단가. 누적 환불액은 결제 금액을 넘을 수 없다.            | 환불 거부   |
| BR-PAY-14 | 환불 완료 시 같은 트랜잭션에서 입장권 상태를 '환불'로, 결제 상태를 부분 환불 또는 환불 완료로 바꾼다. | 롤백      |
| BR-PAY-15 | 환불한 입장권으로 만든 예약이 있으면 함께 취소하고 슬롯 잔여 정원을 복구한다.                 | —       |
| BR-PAY-16 | 환불 사유와 처리 결과(성공·실패, 처리 시각)를 REFUND에 기록한다.                    | —       |
| BR-PAY-17 | 어트랙션 예약 취소는 예약 상태 변경만 하며 환불하지 않는다.                           | —       |

## 4. 어트랙션 (BR-ATR)

운영중 상태인 어트랙션만 예약·추천 대상이며, 이용 예정 예약이 남아 있는 어트랙션은 삭제할 수 없습니다.

| ID        | 규칙                                                                | 위반 시 처리         |
|-----------|-------------------------------------------------------------------|-----------------|
| BR-ATR-01 | 어트랙션명은 공원 내에서 유일해야 한다.                                            | 등록·수정 거부        |
| BR-ATR-02 | 탑승 소요 시간은 1분 이상의 분 단위 정수이다.                                       | 등록·수정 거부        |
| BR-ATR-03 | 각 어트랙션은 이동 시간 계산을 위한 위치(구역 또는 좌표)를 가진다.                           | 등록 거부           |
| BR-ATR-04 | 운영중(OPERATING) 상태만 예약·추천 대상이다. 점검·일시중단·운영 종료는 제외한다.               | 예약 거부, 추천 후보 제외 |
| BR-ATR-05 | 운영중이 아닌 상태로 바꿀 때, 이용 예정 예약이 있으면 관리자에게 예약 건수를 알리고 처리(강제 취소)를 요구한다. | 상태 변경 보류        |
| BR-ATR-06 | 이용 예정 예약이 있는 어트랙션은 삭제할 수 없다. 삭제는 소프트 삭제로 처리한다. (상태 : DELETED)     | 삭제 거부           |
| BR-ATR-07 | 어트랙션 목록은 페이징·이름 검색·이름순/최신순 정렬·예약 가능 여부/운영 여부 필터를 지원한다.            | —               |
| BR-ATR-08 | 키·나이 제한은 추후 개선 항목이며, 도입 전까지 필터만 노출하지 않는다.                         | —               |

### 운영 상태

| 상태               | 의미              | 예약 | 추천    |
|------------------|-----------------|----|-------|
| 운영중 (OPERATING)  | 정상 운영           | 가능 | 후보 포함 |
| 점검 (MAINTENANCE) | 예정된 점검          | 불가 | 제외    |
| 일시중단 (SUSPENDED) | 기상·고장 등으로 임시 중단 | 불가 | 제외    |
| 운영 종료 (DELETED)  | 더 이상 운영하지 않음    | 불가 | 제외    |

## 5. 어트랙션 슬롯 (BR-SLT)

슬롯은 실제 탑승 시작·종료 시각과 정원을 가지며, 잔여 정원은 항상 0 이상 정원 이하로 유지되어야 합니다.

| ID        | 규칙                                                              | 위반 시 처리  |
|-----------|-----------------------------------------------------------------|----------|
| BR-SLT-01 | 슬롯 시각은 실제 탑승 시작·종료 시각이며, 종료 − 시작 = 어트랙션의 탑승 소요 시간이다.            | 등록 거부    |
| BR-SLT-02 | 같은 어트랙션의 같은 날짜 슬롯끼리 시간이 겹칠 수 없다.                                | 등록 거부    |
| BR-SLT-03 | 슬롯은 공원 운영 시간 안에 있어야 한다.                                         | 등록 거부    |
| BR-SLT-04 | 정원은 1 이상이다. 잔여 정원 = 정원 − 예약 완료 건수이며, 0 ≤ 잔여 정원 ≤ 정원을 항상 만족한다.   | 갱신 거부    |
| BR-SLT-05 | 정원을 줄일 때 이미 예약된 인원보다 작게 설정할 수 없다.                               | 수정 거부    |
| BR-SLT-06 | 예약이 1건 이상 있는 슬롯은 시각을 변경하거나 삭제할 수 없다.                            | 수정·삭제 거부 |
| BR-SLT-07 | 잔여 정원이 0이 되면 상태를 예약 마감으로 바꾸고, 취소로 1 이상이 되면 다시 운영 가능으로 바꾼다.      | —        |
| BR-SLT-08 | 운영 중단 슬롯은 예약·추천 대상에서 제외한다. 기존 예약 처리는 BR-RSV-23을 따른다.            | 예약 거부    |
| BR-SLT-09 | 예약 가능 슬롯 조회는 상태 = 운영 가능, 잔여 정원 ≥ 1, 현재 시각 < 예약 마감 시각인 슬롯만 반환한다. | —        |

### 슬롯 상태

| 상태    | 전환 조건                  | 예약          | 추천 |
|-------|------------------------|-------------|----|
| 운영 가능 | 등록 기본값, 잔여 정원 0 → 1 이상 | 가능(마감 시각 전) | 후보 |
| 예약 마감 | 잔여 정원 0                | 불가          | 제외 |
| 운영 중단 | 관리자 변경 또는 어트랙션 운영 중단   | 불가          | 제외 |

예약 마감 시각(시작 30분 전)이 지난 것은 상태값으로 저장하지 않고 조회 시점의 시각으로 판단합니다. 상태를 배치로 바꾸면 타이밍 오차가 생기기 때문입니다.

## 6. 어트랙션 예약 (BR-RSV)

예약은 회원 1명이 슬롯 1자리를 차지하는 것이며, 생성·취소와 잔여 정원 변경은 하나의 트랜잭션에서 처리합니다. 예약과 취소는 모두 슬롯 시작 30분 전까지 가능합니다.

### 예약 생성 검증 순서

예약 요청은 아래 순서로 검증하고, 처음 실패한 항목의 에러 코드를 반환합니다.

1. 회원 상태가 활성인가 (BR-USR-06)
2. 입장권이 유효한가: 소유자·상태·방문일·이용 시간 (BR-TKT-06, 07)
3. 어트랙션이 운영중인가 (BR-ATR-04)
4. 슬롯이 운영 가능 상태이고 예약 마감 전인가 (BR-RSV-02)
5. 같은 슬롯에 이미 예약이 없는가 (BR-RSV-03)
6. 내 다른 예약과 시간이 겹치지 않는가 (BR-RSV-04)
7. 잔여 정원을 원자적으로 1 차감할 수 있는가 (BR-RSV-30)

### 예약 규칙

| ID        | 규칙                                                                                 | 위반 시 처리 |
|-----------|------------------------------------------------------------------------------------|---------|
| BR-RSV-01 | 예약 1건 = 회원 1명의 슬롯 1자리. 입장권을 여러 장 가져도 동반자 몫을 예약할 수 없다.                              | —       |
| BR-RSV-02 | 현재 시각 ≤ 슬롯 시작 − 30분일 때만 예약할 수 있다. 예: 14:00 슬롯은 13:30 이전까지. 정각(13:30:00) 허용 여부는 9장. | 예약 거부   |
| BR-RSV-03 | 같은 회원은 같은 슬롯을 중복 예약할 수 없다(활성 예약 기준 유니크 제약).                                        | 예약 거부   |
| BR-RSV-04 | 같은 회원의 활성 예약끼리 탑승 시간이 겹칠 수 없다(다른 어트랙션 포함).                                         | 예약 거부   |
| BR-RSV-05 | 회원이 동시에 보유할 수 있는 예약 수에는 제한이 없다.                                                    | —       |
| BR-RSV-06 | 예약 생성 시 고유 예약 번호를 발급한다. [제안] 형식 R-yyyyMMdd-8자리 랜덤.                                 | —       |
| BR-RSV-07 | 예약에는 사용한 입장권 ID를 기록한다.                                                             | —       |

### 취소 규칙

| ID        | 규칙                                             | 위반 시 처리 |
|-----------|------------------------------------------------|---------|
| BR-RSV-10 | 본인 예약만, 예약 완료 상태일 때만 취소할 수 있다.                 | 취소 거부   |
| BR-RSV-11 | 현재 시각 ≤ 슬롯 시작 − 30분일 때만 취소할 수 있다.              | 취소 거부   |
| BR-RSV-12 | 취소 시 같은 트랜잭션에서 예약 상태를 예약 취소로, 슬롯 잔여 정원을 +1 한다. | 롤백      |
| BR-RSV-13 | 취소된 예약은 되살리지 않는다. 다시 이용하려면 새로 예약한다.            | —       |
| BR-RSV-14 | 예약 취소에 따른 환불은 없다(BR-PAY-17).                   | —       |

### 예약 상태 전이

| 현재 상태              | 다음 상태             | 주체·조건                    |
|--------------------|-------------------|--------------------------|
| 예약 완료 (RESERVED)   | 예약 취소 (CANCELED)  | 회원(마감 전) 또는 관리자          |
| 예약 완료              | 이용 완료 (COMPLETED) | 관리자 또는 슬롯 종료 후 스케줄러      |
| 예약 완료              | 노쇼 (NO_SHOW)      | 관리자(슬롯 종료 후). 패널티는 추후 정책 |
| 예약 취소 · 이용 완료 · 노쇼 | 변경 불가             | —                        |

### 관리자 처리

| ID        | 규칙                                                                | 위반 시 처리 |
|-----------|-------------------------------------------------------------------|---------|
| BR-RSV-20 | 관리자는 전체 예약을 회원·어트랙션·예약 상태로 필터·검색·페이징 조회할 수 있다.                    | —       |
| BR-RSV-21 | 관리자는 이용 완료·노쇼 처리를 슬롯 종료 이후에만 할 수 있다.                              | 변경 거부   |

### 동시성·정합성

| ID        | 규칙                                                                     | 검증 방법                           |
|-----------|------------------------------------------------------------------------|---------------------------------|
| BR-RSV-30 | 잔여 정원 차감은 조건부 갱신(잔여 정원 > 0일 때만 −1) 또는 비관적 락으로 처리해, 동시 요청에도 정원을 넘지 않는다. | 잔여 정원 1인 슬롯에 동시 요청 100건 → 성공 1건 |

| BR-RSV-32 | 잔여 정원 = 정원 − 예약 완료 건수가 항상 성립한다.                                        | 예약·취소 반복 후 정합성 검사               |
| BR-RSV-33 | Redis 분산 락은 DB 방식으로 요구사항을 만족하지 못할 때만 도입한다.                             | k6 부하 테스트 결과로 판단                |

## 7. 루트 추천 (BR-RTE)

추천은 사용자가 고른 어트랙션만으로, 이동 시간 + 대기 시간 + 탑승 소요 시간이 가장 짧은 유효 루트를 규칙 기반으로 계산합니다. 추천 결과는 예약이 아니며, 예약 시 모든 조건을 다시 검증합니다.

### 입력 조건

| ID                                        | 규칙                                                                                             | 위반 시 처리 |
|-------------------------------------------|------------------------------------------------------------------------------------------------|---------|
| BR-RTE-01                                 | 입력값: 입장권 ID, 이용 시작·종료 시각, 선호 어트랙션 목록.                                                          | 400     |
| BR-RTE-02                                 | 이용 시작 < 이용 종료이고, 둘 다 입장권 이용 가능 시간 안이어야 한다. 시작 시각이 현재보다 과거면 현재 시각으로 보정한다.                       | 400     |
| BR-RTE-03                                 | 선호 어트랙션은 1개 이상, [제안] 최대 5개(5! = 120가지 순서), 중복 불가.추천 경로 계산 시 방문 순서,예약 가능한 슬롯의 조합 및 부분 경로를 탐색한다. |         |
| 응답 시간과 성능 테스트 결과에 따라 선택 가능한 어트랙션 수를 조정한다. | 400                                                                                            |         |
| BR-RTE-04                                 | 입장권은 BR-TKT-06 검증을 통과해야 한다.                                                                    | 거부      |

### 후보 선정

| ID        | 규칙                                                                                                    |
|-----------|-------------------------------------------------------------------------------------------------------|
| BR-RTE-10 | 사용자가 선택하지 않은 어트랙션은 후보에 추가하지 않는다.                                                                      |
| BR-RTE-11 | 후보 슬롯 조건: 어트랙션 운영중, 슬롯 운영 가능, 잔여 정원 ≥ 1, 현재 시각 < 예약 마감 시각, 슬롯 시작 ≥ 이용 시작, 슬롯 종료 ≤ 이용 종료, 입장권 이용 시간 안. |
| BR-RTE-12 | 각 어트랙션은 루트에서 1회만 이용한다.                                                                                |
| BR-RTE-13 | 후보 슬롯이 하나도 없는 어트랙션은 제외 사유(운영 중단, 예약 마감, 정원 없음, 이용 시간 밖)를 기록한다.                                        |

### 시간표 계산

출발점은 정문이며, 출발 시각은 사용자의 이용 시작 시각입니다. i번째 방문 어트랙션의 시간표는 다음과 같이 계산합니다.

$$
\text{도착}_i = \text{출발}_{i-1} + \text{이동}(i-1,\ i)
$$

$$
\text{대기}_i = \text{슬롯시작}_i - \text{도착}_i \quad (\ge 0 \text{ 이어야 유효})
$$

$$
\text{출발}_i = \text{슬롯종료}_i
$$

$$
\text{총 소요 시간} = \sum \text{이동}_i + \sum \text{대기}_i + \sum \text{탑승 소요}_i
$$

| ID        | 유효성 규칙                                          |
|-----------|-------------------------------------------------|
| BR-RTE-20 | 모든 i에서 도착 ≤ 슬롯 시작(늦게 도착하는 조합은 무효).              |
| BR-RTE-21 | 마지막 슬롯 종료 ≤ 사용자 이용 종료(종료 시각까지 이용 완료).           |
| BR-RTE-22 | 루트 안의 슬롯끼리 시간이 겹치지 않는다.                         |
| BR-RTE-23 | 이동 시간은 가상 데이터(분 단위, 대칭)를 사용하며 화면에 '예상값'임을 표시한다. |

### 최적 루트 선정

| 우선순위 | 기준                                                       |
|------|----------------------------------------------------------|
| 1    | 이용 가능한 선호 어트랙션 수가 많은 루트                                  |
| 2    | 총 소요 시간(이동 + 대기 + 탑승 소요)이 짧은 루트                          |
| 3    | 마지막 탑승 종료 시각이 이른 루트 (DEVELOPE에서 구현)                      |
| 4    | 첫 슬롯 시작 시각이 이른 루트(결과를 항상 같게 하기 위한 고정 규칙) (DEVELOPE에서 구현) |

선택 개수가 적을 때는 완전 탐색(순서 × 슬롯 조합)으로 계산하고, 도착이 슬롯보다 늦어지면 그 이후 조합을 탐색하지 않는 가지치기를 적용합니다. 조합 수가 늘어 응답 시간이 목표를 넘으면 동적 계획법을 검토합니다.

### 결과 유형

| 유형                    | 조건                | 응답                               |
|-----------------------|-------------------|----------------------------------|
| 전체 추천                 | 선택한 어트랙션 모두 포함 가능 | 순서, 슬롯, 이동·대기·탑승 시간, 총 소요 시간     |
| 부분 추천 (DEVELOPE에서 구현) | 일부만 포함 가능         | 포함된 루트 + 제외된 어트랙션별 사유            |
| 추천 없음                 | 하나 이상 포함 불가       | 어트랙션별 사유 + '다른 어트랙션을 선택해 주세요' 안내 |

추천 없음은 '후보 슬롯 자체가 없음'과 '후보는 있으나 시간상 루트 구성 불가'를 구분해 안내합니다.

### 기존 예약과 추천→예약 연결

| ID | 규칙 |
|----|------|
| BR-RTE-30 | 추천 계산은 예약을 만들거나 정원을 차감하지 않는다. |
| BR-RTE-31 | 기존 예약 중 예약 시작 시각까지 남은 시간이 30분 이하인 예약이 있다면 새로운 추천 경로 생성을 차단한다. |
| BR-RTE-32 | 추천 루트 예약은 슬롯별로 BR-RSV 검증을 다시 수행한다. 일부 실패 시 성공 건은 유지하고, 실패 슬롯과 사유를 반환해 재추천을 유도한다(전체 롤백 여부는 9장). |
| BR-RTE-33 | 추천 경로를 생성한 후 실제 예약을 시도할 때 기존 예약이 있다면 사용자에게 기존 예약 취소 여부를 확인한다. 사용자의 동의 없이 기존 예약을 자동으로 취소하지 않는다. |
## 8. 공통 규칙 (BR-COM)

모든 시각은 한국 표준시(KST) 기준 분 단위로 다루고, 모든 API는 같은 응답·에러 형식을 사용합니다.

| ID        | 규칙                                                               |
|-----------|------------------------------------------------------------------|
| BR-COM-01 | 모든 시각은 KST(Asia/Seoul) 기준이며, 마감 판단 등 시각 비교는 서버 시각만 사용한다.         |
| BR-COM-02 | 시간 계산 단위는 분이다. 슬롯·이동·탑승 시간은 분 단위 정수로 저장한다.                       |
| BR-COM-03 | 성공·실패 응답은 공통 형식(success, message, data)을 따른다. data가 null이면 생략한다. |
| BR-COM-04 | 비즈니스 규칙 위반은 규칙별 에러 코드로 반환하고, 전역 예외 처리기에서 HTTP 상태로 변환한다.          |
| BR-COM-05 | 이동 시간·대기 시간처럼 실제 데이터가 아닌 값은 화면과 응답에 '예상값'임을 표시한다.                |
| BR-COM-06 | 상태 변경 이력이 필요한 엔티티(예약, 결제, 입장권)는 변경 일시와 변경 주체를 기록한다.              |
| BR-COM-07 | 회원 탈퇴·어트랙션 삭제는 소프트 삭제이며, 조회 시 기본으로 제외한다.                         |

| REFUND_NOT_ALLOWED          | 409  | BR-PAY-11, 12 | 환불 가능 기간이 지났거나 사용한 입장권입니다.    |
| PAYMENT_AMOUNT_MISMATCH     | 400  | BR-PAY-04     | 결제 금액이 주문 금액과 다릅니다.           |
| ROUTE_NOT_AVAILABLE         | 200  | BR-RTE 결과 유형  | 선택한 어트랙션으로 루트를 만들 수 없습니다.     |

추천 없음은 오류가 아닌 정상 결과이므로 200으로 반환하고, 응답 본문에 결과 유형과 사유를 담는 것을 제안합니다.
