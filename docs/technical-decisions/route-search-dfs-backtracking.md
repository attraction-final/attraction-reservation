# 시간 제약이 있는 방문 순서를 DFS + 백트래킹 완전 탐색으로 찾기

> 분류: 기술적 도전 · 관련 이슈: KAN-164 · 기준 코드: `dev` `RouteSearcher`

| 항목 | 내용 |
| --- | --- |
| 문제 | 고른 어트랙션(최대 5개)을 슬롯 시간 안에서 가장 많이, 가장 빨리 도는 순서를 찾아야 한다 |
| 결정 | 순열 공간을 DFS로 내려가며 경로를 붙이고 되돌리는 완전 탐색. 실행 불가능한 가지만 자른다 |
| 근거 | 최대 326개 노드라 전부 봐도 빠르다. 그리디가 1곳만 찾는 경우에 2곳을 찾는다 |
| 한계 | 10개 이상이면 `n!`로 폭발한다. 지금은 요청에서 1 ~ 5개로 막는다 |

## 1. 문제

사용자가 고른 어트랙션(최대 5개)을 어떤 순서로 돌아야 가장 많이, 가장 빨리 탈 수 있는지 정해야 한다. 각 어트랙션은 정해진 시각에만 탈 수 있는 슬롯이 있고, 이용 종료 시각(22:00) 안에 끝나야 한다. 즉 **시간 제약(Time Window)이 있는 방문 순서 문제**다.

## 2. 선택지

| 방식 | 최적 보장 | 문제점 |
| --- | --- | --- |
| 그리디 (가장 가까운 곳 / 가장 이른 슬롯부터) | X | 앞에서 이득을 보고 뒤에서 크게 손해 보는 경우를 놓친다 |
| Held-Karp DP `O(n²·2ⁿ)` | O | n = 5면 이득이 없다. 슬롯·시간 제약과 4단계 비교 기준을 DP 상태에 담기 복잡하다 |
| 휴리스틱 (2-opt, 유전 알고리즘 등) | X | n이 클 때 쓰는 방식. 5개에는 과하다 |
| **완전 탐색 (DFS + 백트래킹)** | **O** | n이 커지면 `n!`로 폭발한다 |

## 3. 결정

순열 공간을 DFS로 내려가며 방문 순서를 하나씩 붙이고, 돌아올 때 방금 선택을 되돌리는(백트래킹) 완전 탐색을 쓴다.

```
searchPaths(현재 경로)
 ├─ 현재 경로를 하나의 추천 결과로 평가 (부분 경로도 후보)
 └─ 아직 안 간 어트랙션마다
     ├─ 이동 구간 없음 → 가지치기 (continue)
     ├─ 도착 후 탈 수 있는 슬롯 없음 → 가지치기 (continue)
     └─ 경로에 추가 → 재귀 → 되돌리기 (백트래킹)
```

결과가 항상 같도록 비교 기준을 4단계로 정해 동점을 없앴다.

1. 포함한 어트랙션 수가 많은 경로
2. 총 소요 시간(이동 + 대기 + 탑승)이 짧은 경로
3. 첫 슬롯 시작이 이른 경로
4. 방문 순서의 어트랙션 ID 사전순

## 4. 근거

- **탐색량이 작다.** 길이 0 ~ 5인 모든 부분 순서는 `1 + 5 + 20 + 60 + 120 + 120 = 326`개다. 어트랙션 5개 × 슬롯 40개 테스트도 1초 안에 끝난다 (`RouteSearcherTest#search_FiveAttractionsManySlots_FinishesFast`).
- **그리디의 반례가 실제로 있다.** 13:00 출발, 이동 5분일 때
  - A 슬롯 `13:05~13:25`, `13:30~13:50` / B 슬롯 `13:10~13:20`
  - 그리디(가장 이른 슬롯): A(13:05~13:25) → B의 유일한 슬롯이 이미 지남 → **1개**
  - 완전 탐색: B(13:10~13:20) → A(13:30~13:50) → **2개**
  - `RouteSearcherTest#search_GreedyFails_FindsMoreAttraction`로 고정했다.
- **가지치기로 불가능한 가지를 통째로 버린다.** 구간이 없거나 도착 후 슬롯이 없으면, 그 뒤에 무엇을 붙여도 그 경로는 성립하지 않는다.
- **부분 추천(PARTIAL)이 자연스럽게 나온다.** 모든 노드를 평가하므로, 5개를 다 못 가도 "가장 많이 갈 수 있는 경로"를 같은 탐색에서 얻는다.

## 5. 한계

- **비용 상한 가지치기(Branch and Bound)는 하지 않는다.** 1순위가 방문 수라서, 지금 소요 시간이 최선보다 길다고 잘라 버리면 더 많이 방문하는 경로를 놓칠 수 있다.
- 선택 개수가 10개 이상으로 늘면(`10! = 3,628,800`) Held-Karp DP나 휴리스틱으로 바꾸는 것을 검토해야 한다.
