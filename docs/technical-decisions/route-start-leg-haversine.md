# 외부 API 없이 첫 구간 추정하기: 하버사인 + 실측 기반 보정

> 분류: 기술적 도전 · 관련 이슈: KAN-140, KAN-142 · 기준 코드: `dev` `HaversineStartLegEstimator`, `RouteRecommendationProperties`

| 항목 | 내용 |
| --- | --- |
| 문제 | 사용자 현재 위치 → 첫 어트랙션 구간은 위치가 매번 달라 미리 측정할 수 없다 |
| 결정 | 하버사인 직선거리 × 우회 계수 1.68 ÷ 보행 속도 52.8m/분, 거리와 시간 모두 올림 |
| 근거 | 두 보정값은 실측 구간 90건에서 구한 중앙값. 외부 길찾기 API 호출이 없어 비용·지연·장애 지점이 없다 |
| 한계 | 실제 길찾기 결과와의 차이는 측정하지 않았다 |

## 1. 문제

어트랙션 간 이동은 실측 데이터가 있지만, **사용자 현재 위치 → 첫 어트랙션** 구간은 위치가 매번 달라 미리 측정할 수 없다. 브라우저 Geolocation이 주는 위도·경도만으로 도보 거리·시간을 구해야 한다.

## 2. 선택지

| 방식 | 문제점 |
| --- | --- |
| 위경도에 피타고라스 | 위도 37°에서 경도 1°는 약 88.7km, 위도 1°는 약 111km다. 도(°) 단위로 그대로 계산하면 동서 방향 거리가 약 25% 틀린다 |
| 외부 도보 길찾기 API | 정확하지만 추천 1건당 5번 호출한다. 비용·지연이 생기고 외부 장애가 추천 장애가 된다 |
| Vincenty (타원체) | 하버사인(구)보다 약 0.5% 정확하지만, 이 정도 차이는 아래 우회 계수의 편차보다 훨씬 작다 |
| **하버사인 + 우회 계수 + 보행 속도** | 직선거리만 나오므로 실제 길로 보정이 필요하다 |

## 3. 결정

```
직선거리       = Haversine(사용자 위치, 어트랙션 좌표)        // 지구 반지름 6,371,000m 구
추정 도보 거리 = ceil(직선거리 × 우회 계수 1.68)
추정 이동 시간 = ceil(추정 도보 거리 / 보행 속도 52.8 m/분)
```

첫 구간은 응답에 항상 추정값(`moveEstimated = true`)으로 표시한다.

## 4. 근거

- **보정값을 감으로 정하지 않았다.** 어트랙션 간 실측 구간 90건과 좌표로 직접 구한 중앙값이다.
  - 우회 계수 1.68 = `실측 도보 거리 / 직선거리` 중앙값 (사분위 1.34 ~ 1.98)
  - 보행 속도 52.8 m/분 = `distance_m / move_minutes` 중앙값 (사분위 46.9 ~ 59.2)
- **올림(ceil)으로 보수적으로 잡는다.** 4.62분을 4분으로 안내하면 사용자가 슬롯에 늦는다. 짧게 틀리는 것보다 길게 틀리는 편이 안전하다.
- **외부 의존이 없다.** 좌표 계산만 하므로 추가 비용·지연·장애 지점이 없다.
- **교체할 수 있게 열어 뒀다.** `StartLegEstimator` 인터페이스로 분리해, 실제 길찾기 API를 쓰게 되면 구현체만 추가하면 된다.
- 보정값은 `application.yaml`의 `route-recommendation.*`로 바꿀 수 있고, 잘못된 값(우회 계수 < 1.0 등)이면 애플리케이션이 뜨지 않는다 (`@Validated`).

## 5. 한계

- 하버사인 추정과 실제 길찾기 결과의 차이는 측정하지 않았다.
- 부동소수점 + `ceil` 함정: 기본값(1.68, 52.8)에서는 발생하지 않지만 설정값을 바꾸면 1분 길게 나올 수 있다. → [첫 구간 추정의 올림·부동소수점 점검](../troubleshooting/route-start-leg-estimation.md)
