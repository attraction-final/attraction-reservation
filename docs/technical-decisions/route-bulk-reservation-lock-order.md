# 추천 경로 일괄 예약: 전부 성공해야 남기고, 어트랙션 ID 순서로 잠가 교착 막기

> 분류: 데이터 정합성 · 동시성 · 관련 이슈: KAN-166 · 기준 코드: `dev` `RouteReservationService`

| 항목 | 내용 |
| --- | --- |
| 문제 | 5곳 중 일부만 예약되면 동선이 깨진다. 방문 순서대로 잠그면 엇갈린 순서의 동시 일괄 예약끼리 교착할 수 있다 |
| 결정 | 한 트랜잭션으로 묶어 하나라도 실패하면 모두 롤백한다. 예약은 어트랙션 ID 오름차순으로 처리한다 |
| 검증 | Testcontainers MySQL 동시성 통합 테스트 4개 |
| 한계 | 실패하면 추천을 다시 받아야 한다. 실패 응답에는 처음 실패한 방문 하나만 담긴다 |

## 1. 문제

추천 결과를 한 번에 예약할 때 두 가지를 지켜야 한다.

- **정합성:** 5곳 중 3곳만 예약되면 추천한 동선이 깨진다. 사용자는 남은 2곳의 시간을 직접 다시 맞춰야 한다.
- **교착:** 기존 예약 생성(`ReservationService#createReservation`)은 슬롯 → 어트랙션 순서로 비관적 잠금을 건다. 방문 순서대로 예약하면, A → B 추천과 B → A 추천이 동시에 들어올 때 서로의 잠금을 기다릴 수 있다.

## 2. 결정

- 일괄 예약 전체를 **한 트랜잭션**으로 묶는다. 방문 하나라도 실패하면 이미 만든 예약과 슬롯 정원 차감까지 모두 롤백하고 409(`ROUTE_RESERVATION_FAILED`)를 돌려준다.
- 예약 순서는 방문 순서가 아니라 **어트랙션 ID 오름차순**이다. 모든 일괄 예약이 같은 순서로 잠금을 잡는다. 응답 목록만 방문 순서로 다시 정렬한다.
- 예약할 슬롯은 클라이언트가 보낸 값이 아니라 **서버에 저장된 추천 결과**에서 읽는다.
- 잠금 대기 초과·교착(`PessimisticLockingFailureException`)과 유일 제약 위반(`DataIntegrityViolationException`)도 "몇 번째 방문이 왜 실패했는지" 담은 같은 오류로 바꾼다.

## 3. 검증

`RouteReservationIntegrationTest`(Testcontainers MySQL)에서 동시 요청으로 확인했다.

| 시나리오 | 결과 |
| --- | --- |
| 두 번째로 처리하는 슬롯이 이미 가득 참 | 409, 먼저 만든 예약과 정원 차감도 롤백 |
| 같은 추천을 동시에 두 번 일괄 예약 | 한 번만 성공, 슬롯마다 예약 1건 |
| 두 회원이 정원 1인 슬롯이 든 추천을 동시에 일괄 예약 | 한 명만 성공, 실패한 회원의 다른 예약도 남지 않음 |
| 방문 순서가 엇갈린 두 추천을 동시에 일괄 예약 | 교착 없이 둘 다 10초 안에 성공 |

## 4. 한계

- 실패하면 사용자가 조건을 바꿔 추천을 다시 받아야 한다. 일부만 예약하는 선택지는 두지 않았다.
- 실패 응답에는 처음 실패한 방문 하나만 담긴다. 그 뒤 방문은 시도하지 않으므로 다른 방문의 실패 여부는 알 수 없다.
